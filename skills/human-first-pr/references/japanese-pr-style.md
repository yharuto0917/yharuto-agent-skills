## 1. `/yomiyasu` 由来の 8 核原則（PR 特化）

### 1.1 意味の保持 4 観点（既存 PR リライト・Diff 要約共通）

1. **主張**: 要点と論理関係（何が・なぜ変わったか）を変えず、論点を別概念にすり替えない。
2. **比重**: 否定対比（「A ではなく B」）の A を並列や優先（「A と B」「まず A」）へ変えない。比較表現では比較対象と差の基準を残す。単なる修辞（「魔法ではなく〜」）のみ肯定文に改める。
3. **言い切りの強さ**: 可能性・推量（「〜場合がある」）、許可（「〜してよい」）、能力（「〜できる」）、義務（「必須」）、保証（「影響なし」）の強度をコード上の事実以上に引き上げない。
4. **文の働き・時制**: 事実・説明・依頼・予定を混ぜない。

### 1.2 情報の不増補 × 未実行テスト捏造防止

- 書ける事実の根拠は次の 3 つだけに限定する: **① `git diff` と実コード、② 実際に実行したコマンド出力、③ ユーザー指示または Issue・提供資料**。一般知識や推測で原因・性能向上率・カバレッジ数値・運用予定を補わない。
- 実行して成功を確認したコマンドのみ `- [x]` とする。未実行テスト・CI 待ち・本番やステージングの目視確認は必ず `- [ ]` へ分離し、未実行である理由を添える（`PR013`）。
- 設定値（例: `retry_wait = 3`）を根拠なく「3 回リトライ」と誤読したり、Diff に根拠のない約束（「今後エラーは起きない」）を書き加えたりしない。

### 1.3 変更報告の述語明記と 4 時制の峻別

地の文で「〜して、処理速度を改善。」のような **`て` 形の体言止め** を禁止する。地の文は「どの設定・実装をどう改めたか」を述語まで言い切り、以下の 4 時制・働きを峻別する（語尾を散らす目的で時制や働きを変えない）。

| 区分 | 文末の形 | 用例 |
|---|---|---|
| **今回の改定（完了）** | 〜を変更した / 〜を削除した | 期限切れ判定の境界条件を改めた（予定風の「〜します」にしない） |
| **システムの現在仕様・実動作** | 〜を返す / 〜を検証する | 失敗時は `401 Unauthorized` を返す（過去形に統一しない） |
| **現在の運用方針** | 〜する方針 / 〜を必須としている | エラーは呼び出し元へ再送出する方針（今回新設したかのように書かない） |
| **未実施・今後の予定** | 〜で対応予定 / 〜を確認する（未実施） | 負荷計測は別 PR で対応予定（`[ ]` チェック項目と連動） |

- 改定前の仕様が Diff や資料から読み取れない場合は、想像で Before を作らない。

### 1.4 補助動詞・形式名詞のひらがな化

補助動詞と形式名詞の漢字「事」「為」はひらがなにする。

- 対象例: `して下さい` → `してください` / `出来ます` → `できます` / `して頂く` → `していただく` / `する事` → `すること` / `する為` → `するため`（`PR019`）。
- 除外対象: 実質名詞（「事の経緯」「為替」）、コード識別子、ファイルパス、引用文字列。

### 1.5 不要読点の排除と残すべき読点

| 扱い | 対象となる箇所 | 具体例 |
|---|---|---|
| **削除する** | 短い主題・主語・目的語（6 字以内目安）の直後、否定対比「なく」の直後、見出し内の読点、短い語句の連続読点 | 「本 PR は、設定を、変更した」→「本 PR は設定を変更した」<br>「A ではなく、B」→「A ではなく B」 |
| **残す** | 外すと掛かり先が変わる所、主題の後ろに別の主語が続く所、長い主語や節のあと、条件・逆接・理由・並列の切れ目、文頭接続語（ただし、また、）のあと | 「この画面では、担当者が件数を入力する」<br>「トークンが期限切れの場合は、401 を返す」 |

- 否定と肯定を 2 文に分けた型（「必要なのは道具ではない。統一することだ。」）は、後ろの文が別主張や根拠補足でない限り 1 文へ統合する。Mermaid コードブロック・引用・表セル・インラインコード内は対象外とする。

### 1.6 比喩動詞・擬人化・直訳語（calques）の具体動作化

- **禁止する比喩動詞・曖昧語**: 「安全側に倒す」「地味に効く」「静かに壊れる / 黙って失敗する」「バグを潰す」「時間を溶かす」「深く踏み込む」「例外を上に逃がす」は使わず、コード上の実処理（例: 例外を送出する、ログを出さずに処理を打ち切る、呼び出し元へ再送出する）で書く。
- **擬人化の境界**: コードや仕組みに感情・意志・人の役目を持たせる表現（「呼び出し元の事情を知っている」「ルーターが交通整理を引き受ける」）は禁止し、何を受け取り・何を返し・何を呼ぶかを書く。一方、`expert`（開発者）向け文書として **識別子・クラス・モジュールが主語の文**（`AuthMiddleware` が 401 を返す、`retry_limit` が上限を決める）と定着した技術表現（テストが通る、キャッシュが効く）は維持する。
- **直訳語と漢語詰まりの回避**: 「ジョブが拾う」「接続が入口を通る」などの直訳表現は「キューから取得する」「API エンドポイントで受信する」へ改める。1 字漢語訳（今回の「版」→ バージョン、修正の「枝」→ ブランチ、PR の「題」→ タイトル、一覧の「頭」→ 先頭）や硬い直訳語（「背景実行」→ バックグラウンド実行、「根因」→ 根本原因、「時間窓」→ 集計期間、「偽緑」→ 誤成功）、助詞落ちの詰まり（「認証失敗時エラー返却」→「認証失敗時はエラーを返す」）、連用形 1 語名詞（「〜の確かめ」→「〜の確認」）を避ける。ただし「確認する」「使用する」「停止する」「動作する」「発生」「復旧」など技術文書で普通の漢語は無理に和語へ崩さない。

### 1.7 分類ラベル箇条書き禁止と太字抑制

- **禁止（分類ラベル＋説明文）**: `- **改善点**: 認証フローを刷新した` や `- **変更内容**: TTL を短縮した` のような分類ラベル＋コロンは **1 件でも禁止**（`PR018`）。ラベルと太字とコロンを外し、意味を 1 文へ統合する（`- トークン検証の TTL を 30 秒へ短縮`）。
- **維持（値ラベル＋値・識別子）**: `- 対象ファイル: src/auth.ts` や `> 🎯 Scope: ...`、`- 依存追加: pydantic（理由1行）` のような「項目: 値」は太字なしで残す。
- **太字抑制**: 300 字超かつ 1,000 字あたり 3.0 個超で出る `excess_bold` 警告を防ぐため、太字は 1,000 字あたり 2 個以下を目安とし、連続する値ラベルや表セル内では `**...**` を付けない。また GitHub で描画が崩れる記号隣接太字（`**「語」**` や ``**`code`**``）も避ける。

### 1.8 `expert` 前提・体言止めの線引き・常体既定

- **読者前提**: レビューする開発者（`expert`）を前提とし、TTL・JWT・N+1・冪等性などの基本技術用語に説明を足さない（例外は Gate 2 要件の **新規追加・更新された依存パッケージの導入理由 1 行** のみ）。
- **体言止めの線引き**: 変更点箇条書き・トリアージ表の「変更理由」セル・チェックリスト項目では簡潔な体言止めを許可し、1 箇条 1 変更を保つ。地の文（TL;DR・解説文）は述語まで書く。
- **文体統一**: 新規生成時は **常体（「だ・である」調）** を既定とし、地の文内で常体と敬体を混ぜない。リポジトリ既存 PR テンプレートや既存 PR 本文リライト（Mode B）で敬体が指定・使用されている場合のみ敬体を維持する。

## 2. 絵文字衝突解消仕様とテンプレート見出し規則

`/yomiyasu` は原則として絵文字を警告対象とする一方、本スキルはトリアージ階層の視認性のために 4 種の構造バッジを用いる。両者を矛盾なく運用するため、許可位置の限定と Text-Only 代替モード切替を設ける（両モードの記法対応表は [mermaid-and-templates.md](mermaid-and-templates.md#2-text-only-モード差分仕様) を参照）。

1. **装飾絵文字の全面禁止（全モード共通）**:
   - 地の文、番号付きセクション見出し（`## 1. ...`）、チェックリスト、設計判断表（`◎ / ○ / △ / ×`）で `🚀 / ✨ / 🔥 / ✅ / ⚠️ / 💡 / 🎉` 等の装飾絵文字を使うことは禁止する（`PR014`）。
2. **Visual Badge Mode（既定: `auto` / `emoji`）の許可位置**:
   - `🎯`: `> 🎯 Scope: ...` 行頭、および `🎯 読むべきファイル` 見出し/ラベル行頭のみ。
   - `🧠`: `🧠 Must-Read` ラベル先頭のみ。
   - `👀`: `👀 Skim` ラベル先頭のみ。
   - `⏭️`: `⏭️ Safe-to-Skip` ラベル先頭のみ（`<summary>` 内含む）。
3. **Text-Only Mode（`--badge-mode text`）への切替条件**:
   - ①ユーザーが「絵文字なし」「テキスト表記」等を指定した場合、または ②リポジトリ内の `CLAUDE.md` / `AGENTS.md` / `.github/pull_request_template.md` / `.yomiyasu-words/` に絵文字禁止ルールがある場合は、自動的に `--badge-mode text`（`[SCOPE]`, `[TARGET]`, `[MUST]`, `[SKIM]`, `[SKIP]`）へ切り替える。
   - 同一 PR 内で絵文字バッジとテキストバッジを混在させてはならない（`PR014` FAIL）。
4. **テンプレート見出し規則**:
   - 新規生成時は Gate 2 で Size S または Size M/L/XL のテンプレートを選択したあと、勝手な `## まとめ` や `## 背景` を足さない。任意節（`## 2.` / `## 4.`）を省く場合は空見出しを残さず連番を詰める。
   - 厳格 `.github/pull_request_template.md` 共存時（`--template-mode strict`）は元テンプレートの見出し名・数・順序を変えない。
   - `yomiyasu_lint.py` は記号・番号を除き 8 字以下の見出し語が本文に出ないと `metaphor_label`（`info`）を出す（例: `## 5. 検証ステータス`）。標準テンプレート見出しへの指摘はポストフィルタで無変更維持とする（§4 参照）。

## 3. PR 特化 AI クリシェ 12 類型言い換え辞書と Good / Bad 7 例

### 3.1 AI クリシェ 12 類型言い換え辞書（`PR005` / `PR006` / `PR016` 対応）

| # | 禁止 AI クリシェ（例） | 欠落している情報 | 書き換え先の具体的挙動 |
|---|---|---|---|
| 1 | **堅牢性を向上 / 安定性を強化** | どの異常をどう防ぐか不明 | 例外条件・リトライ上限・タイムアウト秒数・返却ステータス |
| 2 | **クリーンで保守性の高い設計 / 可読性を向上** | 構造変化の軸が不明 | 分割した責務・廃止した重複・抽出したインターフェース名と依存方向 |
| 3 | **シームレスに統合 / スムーズに連携** | 境界とエラー伝播が隠れる | 受け渡し型・境界インターフェース・失敗時の伝播または非破壊範囲 |
| 4 | **包括的なエラーハンドリング / 適切に処理** | 握りつぶしか再送出か不明 | 捕捉例外型・ログ出力レベル・返却ステータス/エラーコード |
| 5 | **パフォーマンスを大幅に最適化 / 劇的に高速化** | 計算量・クエリ数・計測条件が不明 | 解消手法（N+1 解消、索引追加等）＋実測値と計測条件のみ |
| 6 | **柔軟な対応 / 将来の拡張性を見据えた設計** | 今使わない抽象化の有無が不明 | 今回切り替えた設定項目・具象クラスの現在の利用箇所のみ |
| 7 | **エッジケースを網羅 / リスクを未然に防止** | 「網羅」は検証不能な誇張 | 具体的に考慮した入力条件（空配列・0 件・UTF-8 境界・競合等） |
| 8 | **〜という挙動を排除 / 静かに壊れるのを防ぐ** | 検知・停止の仕組みが不明 | どの条件で処理を中断し、どの例外またはレコードを出力するか |
| 9 | **開発者体験（DX）の向上 / 直感的な API** | 型安全や補完の何が改善したか不明 | 変更した型定義・デフォルト引数・エラーメッセージ改善内容 |
| 10 | **全体の整合性を担保 / 一貫性を確保** | トランザクション境界が不明 | DB トランザクション範囲・一意制約・検証ルール |
| 11 | **What 実況型 diff 解説**（`PR016`: 行番号・手順実況） | Diff を見れば分かる行単位の作業手順 | **なぜ（Why）変えたか** と **外部から観測できる振る舞い変化** のみ |
| 12 | **削減量・作業量アピール**（`PR006`: `200行削減` 等） | Gate 1 は無言整理の義務。ノイズでしかない | 本文から完全削除し、削減行数・割合には一切言及しない |

### 3.2 Good / Bad 7 パターン比較例（TL;DR は日本語 150 字以内）

#### パターン 1: TL;DR — 認証不具合修正（92 字）

- **Bad**: `本PRは、認証モジュールの堅牢性を向上させ、包括的なエラーハンドリングを実現する為の修正です。verifyToken に if (!token) return null を追加し、呼び出し元でも安全側に倒すようにしました。`
  - 違反点: 「本PRは、」の不要読点、クリシェ 2 種、形式名詞「為」の漢字、What 実況、比喩動詞「安全側に倒す」。
- **Good**: `認証トークン期限切れ時に401を返さず再ログインループに陥る不具合を修正した。期限切れ判定の境界条件と再試行上限（1回）を改めたため、リフレッシュ失敗時は即座にログイン画面へ遷移する。`

#### パターン 2: TL;DR — クエリ性能改善（89 字）

- **Bad**: `一覧取得APIを大幅に最適化し、パフォーマンスを劇的に高速化しました！シームレスな統合により、スケーラブルな体験を提供します。`
  - 違反点: 実測条件のない誇張クリシェ、感嘆符による煽り、「シームレスな統合」、曖昧語「体験」。
- **Good**: `一覧取得APIのN+1クエリをJOIN一括取得へ変更し、テスト環境1,000件取得時のSQL発行回数を101回から2回へ減らした。レスポンス型とソート順は既存仕様を維持している。`

#### パターン 3: TL;DR — 非同期ワーカー障害対策（108 字）

- **Bad**: `ワーカーが静かに壊れるバグを潰しました。タイムアウトに踏み込んで、柔軟なリトライ仕組みを導入して、信頼性を改善。`
  - 違反点: 比喩動詞（「静かに壊れる」「潰す」「踏み込む」）、曖昧語（「柔軟な」「仕組み」）、`て` 形の体言止め。
- **Good**: `Webhook送信ワーカーがタイムアウト時に例外を握りつぶしていた処理を改め、30秒超過で失敗ログ出力と遅延キューへの再登録を行うようにした。最大3回の再送後も失敗した場合はdead-letterテーブルへ記録する。`

#### パターン 4: 変更点箇条書き — 分類ラベル排除と値ラベル保持

- **Bad**:
  ```markdown
  - **改善点**: 認証フローをクリーンで保守性の高い設計へ刷新しました。
  - **修正点**: `verifyToken` の実装を見直しました。
  - **注意点**: 再試行回数の挙動が変わります。
  ```
- **Good**:
  ```markdown
  - 未認証リクエストでトークン再取得を試行せず即座に401を返すよう変更
  - `verifyToken` 内の期限切れ判定から猶予時間（clock skew）の二重加算を削除
  - 対象ファイル: `src/auth/verify.ts`
  ```

#### パターン 5: 依存パッケージ理由と設計記述

- **Bad**: `拡張性と将来の柔軟性を見据えた設計のため zod を導入し、バリデーション失敗時は安全側に倒しました。`
- **Good**: `- 依存追加: zod（APIリクエスト境界のランタイム型検証とエラー箇所のフィールド単位返却のため導入）` ＋ 地の文「検証失敗時は再試行せず呼び出し元へ ValidationError を送出する方針に統一した。」

#### パターン 6: 検証ステータス — 未実行テスト捏造防止と状態分離

- **Bad**: `- [x] すべてのユニットテスト・結合テスト・本番動作を確認済み（問題なし）`
- **Good**:
  ```markdown
  - [x] `pnpm test src/auth` を実行し、全14件のユニットテスト通過を確認
  - [x] `pnpm typecheck` 通過（エラー0件）
  - [ ] ステージング環境での実際の期限切れトークン再ログイン挙動確認（手動確認待ち）
  ```

#### パターン 7: 不要読点・`事` 漢字・否定対比・削減アピールの排除

- **Bad**: `本PRは、JWT検証処理を、リファクタリングして、不要コードを200行削減し、セキュリティを担保する事を目的に実施しました。これは単なる修正ではなく、設計の抜本的な見直しです。`
- **Good**: `JWT署名鍵の検証時にアルゴリズム未指定を許可していた設定を改め、RS256のみを受け付けるよう制限した。あわせて期限切れエラーの返却形式をRFC 9457準拠のJSONへ統一している。`

## 4. `/yomiyasu` 未導入時の単体動作と導入時連携・ポストフィルタ規則

### 4.1 `/yomiyasu` 未導入環境での単体動作保証

本スキルは `/yomiyasu` への必須依存を持たない。`/yomiyasu` が未導入、または対象リポジトリに外部設定がない環境でも、本ドキュメント（§1〜§3）と同梱スクリプト `scripts/pr_body_lint.py` だけで構造・日本語・クリシェ検査（`PR005`, `PR006`, `PR013`, `PR014`, `PR016`, `PR018`, `PR019`）を自己完結で実行できる。

### 4.2 `/yomiyasu` 導入済み環境での連携仕様

1. **動的検出と実行コマンド**:
   - `pr_body_lint.py --yomiyasu-lint` 指定時は兄弟/標準配置先（`../yomiyasu/scripts/yomiyasu_lint.py`, `~/.agents/skills/yomiyasu/scripts/yomiyasu_lint.py`, `~/.gemini/config/skills/yomiyasu/scripts/yomiyasu_lint.py`, `~/.claude/skills/yomiyasu/scripts/yomiyasu_lint.py`）の順に探索し、存在すれば次を実行する（未導入時は静かにスキップ）。
   ```bash
   python3 "<yomiyasu_dir>/scripts/yomiyasu_lint.py" --doc-type pr --reader expert --json - < pr_body.md
   ```
2. **使用上の必須ルール**:
   - **`yomiyasu_check.py` は使わない**: 推敲レポート用の固定見出し（`### 書き直した本文` 等）を要求し PR 本文生成と衝突するため。
   - **`--doc-type pr --reader expert` を必ず渡す**: `pr` 種別により `excess_list` が自動除外され、`expert` 指定で識別子主語が適切に保護される。
   - **`--strict` や `--fail-on=warn` を直接渡さない**: Visual Badge Mode の許可絵文字 4 種が `emoji_prohibited`（`warn`）に当たるため、JSON を受け取ってポストフィルタした上で判定する。
   - リポジトリ最上位に `.yomiyasu-words/`（`allow.txt`, `flag.txt`, `flag-patterns.txt`）がある場合は `yomiyasu_lint.py` が自動参照するため、プロジェクト固有の用語統制も自然に反映される。

### 4.3 責務分担とポストフィルタ・出力汚染抑止

| 検査領域 | 主担当（常時: `pr_body_lint.py`） | 補完担当（任意: `yomiyasu_lint.py`） | ポストフィルタと衝突回避 |
|---|---|---|---|
| **PR 構造・Size・Mermaid** | `PR001`〜`PR004`, `PR007`〜`PR012`, `PR015`, `PR017` | 対象外 | 責務完全分離（重複ゼロ） |
| **PR クリシェ・削減自慢・捏造** | `PR005`, `PR006`, `PR013`, `PR016` | 対象外 | `pr_body_lint.py` 単体で保証 |
| **分類ラベル・補助動詞漢字** | `PR018`, `PR019` | `bold_label_list` | 値ラベル（`- 対象ファイル: ...`）は太字を外して誤反応を防ぐ |
| **絵文字制御** | `PR014`（モード別許可・混在禁止） | `emoji_prohibited` | `--badge-mode text` 時は全件有効。Visual Badge Mode 時は **Scope 行頭の `🎯`、および `🎯 読むべきファイル`・`🧠 Must-Read`・`👀 Skim`・`⏭️ Safe-to-Skip` の許可位置だけからなる行** の `emoji_prohibited` を除外し、装飾絵文字のみ採用する |
| **深層文法・直訳語** | 重複実装しない | `pause_comma`, `metaphor_verb`, `calque`, `ai_phrase`, `renyo_noun`, `bold_not_rendered` | 導入時のみ精度を上乗せする |
| **テンプレート見出し** | 構造存在確認 | `metaphor_label`, `short_summary_heading` | `short_summary_heading`（「まとめ」禁止）は有効化。`## 5. 検証ステータス` 等の標準見出しへの `metaphor_label` はポストフィルタで除外する |

- **出力汚染の厳格抑止**: `yomiyasu_lint.py` を連携実行しても、`/yomiyasu` 形式の報告見出し（`### 書き直した本文`、`### 変えたところ`、`### 確認の記録`、`yomiyasu-check:` 行）は PR 本文にも最終出力にも一切出さない。
